# Правила проекта для AI-агентов и разработчиков

Этот файл читают AI-ассистенты (Claude Code, Cursor, Copilot и др.) и участники команды. Сначала прочитай `docs/spec.md`.

## Что строим

Справочный чат-бот онкодиспансера: поиск по утверждённой базе знаний, обязательный источник, правила безопасности, передача вопроса специалисту. Границы MVP — в `docs/spec.md`.

## Жёсткие правила (нарушать нельзя)

1. **Никаких медицинских формулировок от себя.** Тексты ответов берутся только из записей базы знаний со статусом `approved`. Если текста нет — заглушка с пометкой `ТЕСТОВЫЙ КОНТЕНТ`.
2. **Каждый ответ с источником.** Ответ без `source` — ошибка.
3. **Бот не назначает лечение.** Вопросы о дозировках, приёме лекарств, диагнозах, экстренных симптомах обрабатываются правилами безопасности **до** поиска.
4. **Нет персональных данных.** Не сохраняем и не логируем ФИО, телефоны, даты рождения, номера карт. В тестах — только синтетика.
5. **Секреты не коммитим.** Ключи API, пароли и `.env` — только в `.env`, файл в `.gitignore`.
6. **Не выдумываем факты заказчика.** Адреса, телефоны, часы работы — только из источника, который указан в записи базы.

## Технологии (MVP)

- Python 3.11+, FastAPI, SQLite (FTS5).
- Лемматизация русского языка: `pymorphy3`.
- Фронтенд: простой HTML/JS (виджет и страница оператора).
- LLM в MVP не используется. Если появится — только для переформулировки утверждённого текста, с проверкой на отсутствие новых фактов.

## Структура репозитория

```
docs/          спецификация, протоколы встреч, архитектура, глоссарий
app/           код приложения (будет создан)
data/          база знаний (FAQ, утверждённые тексты)
tests/         тесты и тестовый набор вопросов (questions.csv)
AGENTS.md      этот файл
```

## Работа с кодом

- Перед изменением поведения бота — обновить `docs/spec.md` (SDD: сначала спецификация, потом код).
- Новая функция — отдельная ветка `feature/<короткое-имя>`, в `main` — через merge после проверки.
- Коммиты в формате `type: описание` — `docs:`, `feat:`, `fix:`, `test:`, `refactor:`.
- Каждое изменение правил безопасности сопровождается тестом на соответствующий вопрос из `tests/questions.csv`.
- Не удалять тестовые вопросы, чтобы не ломать метрики — только добавлять.

## Тесты и метрики

Перед слиянием в `main` запускаются тесты. Метрики из `docs/spec.md` (раздел 7):
- безопасность: 100% вопросов с назначениями получают отказ;
- источники: 100% ответов содержат `source`;
- поиск: доля правильных записей в top-3 — фиксируется и не должна падать.

## Что делать, если не знаешь

Не угадывать. Добавить вопрос в `docs/open-questions.md` и спросить владельца проекта.
